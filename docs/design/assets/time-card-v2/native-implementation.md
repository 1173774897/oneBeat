# 漫画整卡版：正式打卡页面

## 入口与范围

新增 `entry/src/main/ets/pages/TimeCardCalibrationPage.ets`，路由为 `pages/TimeCardCalibrationPage`。

正式入口路径：**队伍大厅 → 耳机校准 → 播放蓝牙试音 → 声音在蓝牙耳机里 → 漫画整卡页**。确认按钮统一进入`TimeCardCalibrationPage`，移除重复的「体验漫画整卡版」按钮。旧`AudioCalibrationPage`源文件保留，六张PNG与旧美术资源并存。

新页使用真实 120 BPM / 4 拍预听 / 32 次触摸采样，调用既有 `AppSession.scheduleLatencyTapMeasurement`、试听与持久化接口。样本时间先提交，再排队播放冲孔；每次有效触摸对应一孔和一轮扳手下压，不以动画时间测量延迟。

## 已实施的画面与交互

- 纸卡位于后导轨与前盖之间，下缘进入机口后被前盖和托纸窗口裁切。
- 扳手围绕右侧银色轴心转动；独立冲头压下，导向座与底模保持支撑。导向座与冲头先试制 45°，随后按更明显的约 60° 俯视统一重绘。支撑臂保持镜头正前侧灰色一体结构，上套 U 形开口透明；导向座不随下压。
- 纸面只使用竖直 `blank-time-card.png`，不把梯形位图强行拉回正面。纸图、32 孔、印章和文字在同一容器，打孔时由 ArkUI 原生 X 轴旋转产生上窄下宽的透视；每进一行补偿横向尺度，使当前四列打孔区始终等于进料区域。旋转和缩放明确共用纸面锚点。八行均落在相同 X 工位和 `PUNCH_PLANE_Y=686`。
- 测量进度只有一处 `n / 32` 数字；垫子上无另一组进度点。预备小节显示与行进页相同的4、3、2、1扩散淡出倒数，按已安排的四拍时钟计算；正式测量起点立即隐藏，不改变32次采样或首拍蓝牙延迟容忍窗口。
- 中断立即停止采样和音频内容；收杆后原卡退回，保留真实孔并标记「本次未完成」。漏拍、两次敲击太近、首拍未接到、连接中断、会话结束使用不同文案。
- 中断至少收束 1 秒，手指松开后才能重试。旧卡连同孔退出后，才装空白卡、清空本轮数据，并重新听完整一小节。中断不保存、不覆盖已有校准。
- 完成 32 次后先停音频，等所有冲孔动作排空再退卡。退出后，旋转角归零、宽度补偿归一，纸面恢复无透视的正面。原竖直纸素材、32 个孔及文字共同转正；结果四列横向等距、八行纵向等距。取卡前300ms内断开蓝牙时，直接落实完整竖直结果姿态，避免转正定时器被取消后留下梯形；保存仍受连接状态限制。
- 结果可校准前/后试听。保存、重测位于结果说明之后，以12vp普通间距跟随内容滚动，不再强制结果阅读区占满视口。漏拍重测同样位于说明下方并跟随滚动；换卡期间保留原位置的禁用按钮。完成、重测后回到顶部。保存时禁用试听、重测和返回，沿用保留测量 renderer 的保存协议。

### 导向座露出量修正

用户在 PNG 内把导向座上移了 134 源像素，已保留这张图。它经 `.166 × sceneWidth/1254` 缩放后，360vp 场景中只上移约 6.4vp；前盖仍在 z=5 遮挡 z=4 的导向座。底模源坐标随内容从 y639 改为 y505，重新配准后仍对齐 y686 工作面。前盖 y 从75改为110，遮挡边从约683.08降到718.08，露出工作面下方约32设计像素。不要单独提高导向座层级，否则底脚会画到红盖板前面。浏览器需刷新读取改图，已安装 HAP 则需要重新构建/安装才能包含新图。

### 单一竖直纸素材与送料补偿

旧实现只做纵向比例恢复，无法去掉用户替换的梯形 PNG 自带的收窄，因而结果仍是俯视轮廓。现仅使用原竖直 PNG；用户的梯形图及备份完整移到 `archive/paper-perspective/`，没有改图或丢弃。无需新增纸素材。

以源坐标 `a=1020, c=628, p=.0003, d=.966`，纸面分母 `D(y)=1+p*(a-y)`。第 r 行来到冲头时，整体横向补偿 `sx=D(1020-r*82)`，投影为 `x'=c+sx*(x-c)/D(y)`、`y'=a+d*(y-a)/D(y)`；纸的 y 设为 `686-.68*y'(当前行)`。这样四个工位 X 恒为455.6、557.6、659.6、761.6，第八行不会比首行窄。当前补偿从1增加到1.1722，变化与送料动画同步。墨层不单独变形，结果把 d=1、sx=1，旋转角变为0，整个变换回到无透视正面。

原生页使用 `paperScale(): ScaleOptions` 与 `paperRotation(): RotateOptions`，共享 vp 锚点 `(628,1020) × cardScale × q()`。角度为 `acos(d)`（当前约15°，对应约75°俯视），相机位于负 Z；源距离为 `sqrt(1-d²)/p`。Rosen 的相机位置直接交给 Skia，后者按72像素/英寸换算，因此接口值是 `-vp2px(源距离 × cardScale × q())/72`。结果转正时保留有限相机距离，避免距离过零造成画面消失。预览继续使用等价 CSS `matrix3d`。调整视觉透视首选 p/depth，调整进料区域宽度首选 `CARD_SCALE`，不要直接修改逐行 sx。

### 真机只露出右侧纸边的修正（2026-10-14）

用户确认问题出现在真机漫画打卡页，打开及打孔时只在前盖右侧露出一点纸边。此前测试把 `matrix4.init` 模拟成原数组并直接投影，只验证了数学结果，没有覆盖 ArkUI 实际矩阵分解及默认中心行为。不能据此认定真机呈现正常。

[ArkUI 官方说明](https://github.com/openharmony/docs/blob/master/zh-cn/application-dev/reference/apis-arkui/arkui-ts/ts-universal-attributes-transformation.md)要求透视矩阵使用 API20 起的 `transform3D`，并明确二维 `transform` 可能显示错误。项目兼容 API12，改用 API10 已支持的原生旋转与缩放，避开二维矩阵分解路径，同时明确共同旋转中心，修正可能的默认中心偏移。没有通过挪纸或提高纸的层级绕过机身遮挡。相机换算核对了 [Rosen 相机组合](https://raw.githubusercontent.com/openharmony/graphic_graphic_2d/master/rosen/modules/render_service_base/src/common/rs_obj_abs_geometry.cpp)与 [Skia Camera](https://raw.githubusercontent.com/google/skia/main/src/utils/SkCamera.cpp)实现。

测试现在投影实际传给原生的旋转/缩放参数，检查相机符号、72倍单位换算、共享中心、不同屏幕密度，以及初始和八行进料时的纸面宽带是否仍位于裁切窗内、前盖上缘以上。实际真机显示仍待安装此修复包确认。

### 完成后惯性点击误保存（2026-10-15）

用户反馈第32次打孔结束后，多点一下仍会直接保存，来不及查看结果。仅把按钮放回普通滚动内容不足以避免这个问题：旧实现一设置`phase='result'`便挂载并启用保存，`finishAndSave`没有结果阅读或新手势条件，结果页触摸也没有纳入原打孔区的`touchHeld`跟踪。

现在取卡的350ms动画由原生`onFinish`确认完成后，至少留出1000ms结果阅读时间；同时要求手指已经松开且700ms内没有新的按下、松开或取消。700ms超过当前500ms拍距，因此连续惯性跟拍时不会在两拍间隙解锁。门槛满足前，保存显示“请先查看结果”，保存与重测均不可用。结果仍可正常滚动，按钮沿用普通内容流和原12vp间距。
